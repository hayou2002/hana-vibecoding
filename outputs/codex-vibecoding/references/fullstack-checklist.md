# 全栈环节检查表

只展开与本次变更相关的项目。使用仓库现有标准；具体框架 API 以安装版本的官方文档为准。

## 产品与 UI

- 目标用户、核心任务、验收与非目标明确；关键内容优先，不用占位文本伪装完工。
- 设计方向、字体、色彩、密度和动效有意图；沿用现有设计系统，避免默认模板化观感。
- 覆盖 loading / empty / error / success / disabled；提交、刷新、导航或关闭时状态行为明确。
- 窄屏、键盘焦点、语义 HTML、表单 label、错误提示、对比度与 reduced-motion 符合场景要求。
- 图片有 alt 与尺寸/裁切策略；长列表、慢网及大资源不导致明显卡顿或布局跳动。

## 前端与客户端状态

- 客户端只承担交互必需状态；服务端事实与缓存策略清晰，不用多份状态源互相覆盖。
- 表单客户端体验与服务端校验一致；防重复提交；失败保留必要输入并给可理解反馈。
- URL 是否应表达筛选、分页、选中对象或可分享状态；返回键与刷新不会无意丢失预期状态。
- 数据获取避免不必要的串行瀑布、重复请求与过量 bundle；性能优化由实际路径/测量驱动。

## API 与业务逻辑

- 请求/响应 schema、HTTP/领域错误、分页、排序、筛选、空结果与兼容策略一致且有文档/类型。
- 对所有不可信输入在服务器边界验证；服务端重新检查认证、授权、资源所有权和租户隔离。
- 区分 400/401/403/404/409/429/5xx 等适用语义；不把内部堆栈、SQL、token 或隐私数据返回给客户端。
- 非幂等写入考虑重复提交/重试；并发更新、速率限制、超时与第三方故障策略按实际风险决定。
- 外部 API 失败、超时、速率限制、部分成功与密钥轮换有可观察、可恢复策略；密钥只在可信服务器端。

## 数据库、迁移与文件

- Schema 由真实数据访问路径推导；明确主外键、唯一性、可空性、删除语义、索引和时间/金额表示。
- Migration 能处理已有数据与当前生产版本；数据回填、锁表风险、上线顺序和回滚/前滚策略有说明。
- 用户级数据始终按服务端身份隔离；应用层过滤不是唯一的授权防线。必要时启用数据库级策略/约束。
- 种子、fixture 与真实数据隔离；不把生产数据复制到测试或日志。
- 文件上传限制大小/类型并验证内容；使用非猜测式对象 key、授权下载、存储生命周期与恶意文件策略。

## 测试、运维与交付

- 单元测规则，集成测数据库/API 边界，端到端测关键用户旅程；断言行为而不是只断言实现细节。
- 重要 bug 有回归测试；授权/租户隔离、迁移和重试幂等尤其需要失败路径覆盖。
- CI 检查与本地检查一致；检查锁文件、构建产物、运行/健康检查和环境变量清单。
- 日志/指标能定位失败而不暴露 secret/PII；重试、限流、超时、资源释放与 graceful shutdown 匹配服务形态。
- 依赖变更说明理由并核对许可/维护状况；部署前识别兼容窗口、回滚与数据不可逆点。
- 部署方案记录 preview/staging/production 区分、CI 门禁、环境变量名、secret 提供方式、健康检查、日志/告警和回滚路线。
- 生产迁移与代码发布能否兼容部署顺序明确；评估备份、锁表/长事务、回填、前滚或回滚。
- 部署后核实目标环境/版本、健康状态、关键路径和目标侧回读；仅在授权的环境执行变更。

## 安全快速检查

- 身份认证与访问控制：每个对象/动作验证授权；不能相信隐藏按钮或客户端角色字段。
- 注入与输出：参数化查询；HTML/模板输出按上下文编码；不将不可信值直接拼进 shell、SQL、路径或 DOM。
- 浏览器与 API：审视 CSRF、CORS、cookie、CSP、速率限制与敏感信息缓存策略，按实际架构应用。
- 密钥与敏感数据：不入仓库、客户端 bundle、URL、截图或日志；轮换泄露凭证，避免扩大访问权限。
- 依赖和供应链：使用项目包管理器及锁文件；评估新依赖来源、维护、权限和已知漏洞。
- 专项安全审计时使用 OWASP ASVS / Cheat Sheet 或平台安全指南作检查来源，报告范围与遗漏；不能宣称普通 lint 或单测就是安全认证。
